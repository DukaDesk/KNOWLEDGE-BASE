# TASK-0027: Fix forgot-password flow (send reset email, validation, UI cleanup)

## Parent Feature

- [FEAT-0001 Identity Foundation](../features/FEAT-0001.md)

## Engineering Specification

- [SEC-0001 Authentication Architecture and User Identity](../../engineering-specifications/specifications/security/SEC-0001.md)

## Repository Target

- backend/ (+ frontend fix in dukaDesk/)

## Description

The forgot-password flow is a silent dead end: `RecoveryService.requestReset` generates the reset token, stores it in Redis, and only writes it to the server console log — no email is ever sent, despite a working `EmailAdapter` (Resend) being configured and used by the OTP flow. The frontend promises an inbox link that can never arrive.

Findings to fix:

1. **No email sent** — `src/modules/iam/recovery.service.ts` never calls `EmailAdapter`; token only logged.
2. **TTL mismatch** — UI promises 15 minutes, backend TTL is 60 minutes. Standardize on **15 minutes**.
3. **No validation DTOs** — missing email → Prisma 500; missing password → TypeError 500 (must be 400).
4. **Case-sensitive email lookup** — differently-cased registered emails silently get nothing.
5. **Frontend dead code** — unreachable OTP step, `handleResendOtp` sends empty email, `otp` field ignored by backend, dead path-segment token fallback.
6. **Zero test coverage** for the whole flow.
7. Docs claim "Send reset link" which is currently false.

## Acceptance Criteria

- [ ] `POST /api/v1/auth/forgot-password` sends a real email (via `EmailAdapter`, Resend) containing `{RESET_LINK_BASE_URL}/reset-password?token=…`; unknown emails still return the generic non-enumerating response with no email.
- [ ] Token TTL is 900s (15 minutes), matching the UI copy; delivery failure deletes the Redis token and returns 503 (no ghost tokens).
- [ ] Email lookup is trimmed and case-insensitive.
- [ ] Invalid/missing inputs return 400 validation errors (DTOs), never 500.
- [ ] `POST /api/v1/auth/reset-password` unchanged in contract (`{ token, password }`): strength + 5-history checks, refresh-token revocation, single-use token.
- [ ] dukaDesk frontend: dead OTP/path-fallback code removed, `otp` dropped from payload, 15-minute copy kept.
- [ ] Unit tests: backend `recovery.spec.ts` (send/failure-rollback/unknown-email/expiry/strength/history/case/validation) + frontend API tests — all green.
- [ ] E2E: request reset from `localhost:3000/forgot` against local backend → real email received → link opens `/reset-password?token=…` → password set → login succeeds.
